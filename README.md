# Battleship REST Service

Сервис для игры «Морской бой» на FastAPI и турнирная арена для проведения матчей между сервисами.

## Возможности сервиса

- генерация стандартного флота на поле 10×10: 10 кораблей и 20 палуб;
- проверка состава флота, прямизны и непрерывности кораблей, границ поля, пересечений и касаний;
- создание игровой сессии с возвратом `session_id` и расстановки флота;
- хранение сессий, расстановок, входящих и исходящих выстрелов в PostgreSQL;
- обработка выстрелов противника с результатами `miss`, `hit` и `killed`;
- выбор собственных выстрелов без повторов и добивание повреждённых кораблей;
- приём результата собственного выстрела;
- закрытие игровых сессий;
- изоляция состояния разных партий и защита от конфликтующих параллельных изменений одной сессии;
- запуск приложения и PostgreSQL через Docker Compose с автоматическим применением миграций Alembic.

## Возможности арены

- создание отдельных игровых сессий у двух участников;
- обмен выстрелами и результатами через HTTP;
- сохранение хода после `hit` и `killed`, смена игрока после `miss`;
- проведение матча до потопления всего флота и фиксация победителя;
- независимые попытки закрыть обе сессии после матча, запись ошибок закрытия в журнал;
- проверка расстановок, координат, повторных выстрелов и достоверности ответов по известному полю;
- таймаут `1.0` секунды в настройках HTTP-запросов;
- техническое поражение при нарушении правил, таймауте, ошибке соединения, HTTP-ошибке или некорректном игровом ответе;
- проведение турнира: каждая пара участников играет один матч, за победу начисляется одно очко;
- вывод всех победителей при равенстве максимального счёта;
- сохранение результатов и истории выстрелов в JSON.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | `/game` | Создание сессии и получение расстановки |
| POST | `/game/{session_id}/opponent-shot` | Обработка выстрела противника |
| POST | `/game/{session_id}/shot` | Получение координаты собственного выстрела |
| POST | `/game/{session_id}/shot/result` | Передача результата собственного выстрела |
| POST | `/game/{session_id}/close` | Закрытие игровой сессии |

Координаты передаются в формате `A1`–`J10`. Подробные схемы запросов и ответов доступны в Swagger.

## Настройка окружения

Создайте `.env` на основе `.env.example` и укажите параметры PostgreSQL.

В PowerShell:

```powershell
Copy-Item .env.example .env
```

## Запуск сервиса

```powershell
docker compose up -d --build
```

Миграции применяются автоматически перед запуском приложения.

Swagger: http://127.0.0.1:8000/docs

## Тесты

Полный набор тестов, включая работу с PostgreSQL и параллельные запросы:

```powershell
docker compose exec app python -m pytest -q
```

## Запуск арены

Арена запускается из папки проекта в локальном Python-окружении. Для подготовки окружения в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если окружение уже подготовлено, достаточно активировать его.

Для турнира укажите минимум два разных локальных порта запущенных сервисов:

```powershell
python -m arena.main 8000 8001
```

Повторные порты и значения вне диапазона `1`–`65535` отклоняются до запуска матчей.

Отчёт записывается в `reports/tournament.json`. Он содержит очки, победителей, результаты матчей, причины технических поражений и историю выстрелов. Следующий запуск перезаписывает файл.

### Проверка на двух экземплярах приложения

Запустите основной сервис через Docker Compose. Затем запустите второй экземпляр на порту `8001`:

```powershell
docker compose run --rm -d --no-deps --name battleship-arena-second -p 127.0.0.1:8001:8000 app python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Оба экземпляра используют одну базу PostgreSQL, но создают отдельные игровые сессии. После готовности второго экземпляра запустите арену:

```powershell
python -m arena.main 8000 8001
```

Для остановки второго экземпляра:

```powershell
docker stop battleship-arena-second
```

Контейнер второго экземпляра удаляется автоматически. Основной сервис и база продолжают работать.

## Этапы разработки

- Неделя 3: генератор и валидатор стандартного флота.
- Неделя 4: создание сессии, сохранение расстановки в PostgreSQL и приведение API к финальному контракту.
- Недели 5–6: обработка выстрелов противника, собственные выстрелы, добивание кораблей и приём результатов.
- Недели 7–8: закрытие сессий, изоляция партий и проверка параллельных запросов.
- Неделя 9: полная партия между двумя сервисами, очерёдность ходов, определение победителя и турнир.
- Неделя 10: проверка достоверности ответов, обработка таймаутов и ошибок сервисов, сохранение отчёта.

Проведена локальная проверка полного матча между двумя экземплярами приложения на разных портах.
